## Architecture and implemented source

The reusable OBS v5 core uses pinned `goobs v1.8.3`; generic commands configure
connections lazily, preserving offline help/version/reference/completions. The
public `pkg/api/v1` facade provides independent models/errors, contextual bounded
operations, serialized lifecycle, explicit invocation approvals and schema1 JSON.
The new API CLI consumes it. Legacy `internal/obs` commands retain their older
acknowledgement/output contracts as a compatibility path.

The managed Deck runtime owns only its isolated graphical OBS Flatpak and local
state. It uses bundled authenticated obs-websocket, valid rendered capture and
fresh output bytes. Desktop/Decky adapters invoke the same local JSON boundary.
Game-only capture fails to intentional idle, never silently to whole-display.
Recording/replay/streaming and requested/observed/unknown state stay distinct.

The new mixer stores non-secret stream-source preferences, observes actual
inputs/gain/mute/meters, mutes route/device changes and uses a bounded private
hold-to-talk guardian. It does not change host volume/default input or promise
physical mute while OBS control is unavailable. Hardware and actual controller
behavior remain target evidence.

Creator orchestration consumes the public facade and private environment-backed
RTMP transport adapters. It connects to existing OBS, leaves it running and
performs no provider account API/OAuth, remote upload or simultaneous multistream.
Canonical governance/security/support docs, pinned local CI and deterministic
release auditing are implemented. Draft Identity assets/migration/site preparation
remain separate from approved current product visuals.
