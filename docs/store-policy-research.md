## AI wording needs clarification

The [submission guide, lines35–37](https://github.com/SteamDeckHomebrew/wiki/blob/ec9d4cf8b07cdc7bc7706fd118d68a272f653cb4/plugin-dev/submitting-plugins.md#L35-L37), last changed 2025-11-27, says: “We do not accept any plugin that uses any LLM based code.” It separately says LLM-focused plugins will be rejected with no appeals. That is the maintainers' written rule and rationale, not an independently established interpretation of copyright/GPL law.

The newer [addition template, lines32–36](https://github.com/SteamDeckHomebrew/decky-plugin-database/blob/0fdb6a686d7c0e79366f85c9d551576cad3ecee5/.github/PULL_REQUEST_TEMPLATE/plugin_addition.md#L32-L36) instead asks the submitter to attest: “Generative AI was NOT used to write a majority of the code I am submitting.” The current [safety page, lines23–30](https://github.com/SteamDeckHomebrew/wiki/blob/ec9d4cf8b07cdc7bc7706fd118d68a272f653cb4/user-guide/plugin-safety.md#L23-L30) lists “Excessive use of generative AI to develop the plugin” among denial reasons. PR#1025's rationale likewise says excessive use is unsafe/unwanted and links both wiki pages.

This is a real difference, not evidence that either text can be ignored. The truthful project history discloses AI assistance, and no audited percentage is available. Do not assert “not a majority,” infer acceptance from successful code review, conceal provenance, rewrite history, or present retyped generated code as independently human-authored to manufacture an attestation. Owner-approved clarification of which current rule governs and how it applies to the actual disclosed project is the smallest Store-policy next step. Waiting for a policy change or choosing direct-only distribution are valid dispositions.

## Paid features, support buttons and direct downloads

The [monetization guide](https://github.com/SteamDeckHomebrew/wiki/blob/ec9d4cf8b07cdc7bc7706fd118d68a272f653cb4/plugin-dev/submitting-plugins.md#L18-L33) says financial features involving significant server/service expense or peripheral functionality are *likely* accepted; charging for core functionality or accessibility is *likely* denied; some elsewhere-accessible features depend on context. Final approval is discretionary. It explicitly asks developers to ask before implementing an uncertain paid feature. No paid feature/service is selected here.

The inspected policy pages/templates do not explicitly settle voluntary donation-button or cryptocurrency-link treatment. That is an evidence gap, not blanket approval or a discovered prohibition. Keep core/local/offline/accessibility behavior free; recipient/control/readiness, channel-specific link treatment and any financial terms remain owner facts. Do not invent a Store rule banning all donations or equate voluntary support to paywall approval.

Manual ZIP/URL installation is explicitly described by the [submission guide](https://github.com/SteamDeckHomebrew/wiki/blob/ec9d4cf8b07cdc7bc7706fd118d68a272f653cb4/plugin-dev/submitting-plugins.md#L11-L16) and [template README](https://github.com/SteamDeckHomebrew/decky-plugin-template/blob/90d0780e882a17f5714fc6de044c645f22608290/README.md#L69-L92). The newer [safety guide](https://github.com/SteamDeckHomebrew/wiki/blob/ec9d4cf8b07cdc7bc7706fd118d68a272f653cb4/user-guide/plugin-safety.md#L49-L56) strongly discourages it, says the Decky team will not support non-Store plugins, and recommends open source and reputable downloads. Thus direct distribution is a legitimate technical path, not Decky endorsement. Its publisher owns trust, reproducible/download verification, updates, rollback, support and clear instructions. Store review is an additional review/testing/channel benefit but adds policy/layout/update/native-test gates and cannot be promised.
