Check before replacing files

Check for updates queries the configured release channel and reports app, plugin and updater versions. It does not install anything or interrupt an active stream. A source PR is not a published runtime release.

  1. Stop streaming and recording and wait for confirmed status. If output is unknown, inspect OBS and the channel first.
  2. Use the bundled Desktop updater or exact reviewed unified installer.
  3. Verify the candidate version, source revision, checksums and qualification limits. Preserve the existing installation and keys.
  4. After upgrading, confirm matching app/plugin versions, make an audible local clip, then perform an explicit viewer test.

Repair and rollback

Rerunning the supported unified installer is the normal repair path; do not delete random plugin files or ordinary OBS settings. Keep the terminal result visible and read the named failure. A matching-version repair should preserve existing configuration.

Rollback must use the updater's verified retained installation path and source-specific instructions. Do not point the installed symlink at an arbitrary download or bypass active/unknown-output checks. Retained backups are not a substitute for a tested rollback receipt.

Offline and failure behavior

An unavailable GitHub connection or rate limit should leave the installed version usable. Checking requires network access; local help, settings and supported local operations do not require a funding account. Broadcasting still requires your provider connection.

The owner is still choosing the final organization. Repository transfer and updater trust changes require a coordinated transition; redirects alone do not establish safe migration.
