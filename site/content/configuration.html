Sensible defaults, explicit control

Keep configuration predictable.

The working display name is @@DISPLAY_NAME@@. Existing CLI, storage and plugin identities remain compatible.

Two configuration purposes

Managed Deck setup stores stream/capture settings in $XDG_CONFIG_HOME/obsgod/deck.json and private credentials in secrets.json. The default config root is ~/.config. Desktop setup and the Decky adapter share this store.

The reusable OBS CLI uses a separate versioned obsgod/config.json connection file. Milestone 2 precedence is flags → OBSGOD_* environment variables → legacy OBS_* aliases → selected connection profile → file connection → defaults. A connection profile is not an OBS scene/profile selection.

obsgod --help
obsgod config path
obsgod config show --json
obsgod config validate --json
obsgod config profiles --json
obsgod version --json
obsgod completion bash

Choose connection configuration with --config and --connection-profile. Use --password-file or a documented private secret reference instead of putting credentials in command history. Inspect the source-specific command help before scripting.

Directories and Decky context

Config, data, state and cache follow their respective XDG roots. Temporary IPC uses XDG_RUNTIME_DIR. The private OBS Flatpak profile stays under its sandbox-accessible application tree; ordinary OBS profiles remain separate.

The adapter uses Decky's supplied plugin/user context. Its persistent DECKY_PLUGIN_RUNTIME_DIR is not the temporary XDG runtime directory. Shared application settings do not move into a second, disconnected Decky-only credential store.

Existing identifiers such as obsgod, OBSGod and Videos/OBSGod are intentional compatibility names while migration is reviewed.

Capture modes and audio

Entire screen includes visible Steam menus and other screen content. Game only requests compatible app-filtered Gamescope capture; when no game can be verified, it uses the selected black or plain-text between-game screen. It never silently substitutes full-screen capture.

Change capture mode only while streaming and recording are confirmed stopped. A game is not required for the OBS control connection. Game-only capture still depends on the compositor exposing and honoring the required app-filter format.

Audio uses the selected system output monitor and may include other applications. Game-only video is not per-application audio isolation. Microphone is opt-in. Check an audible local clip and a live viewer; a moving meter alone is not proof.

Private connection recovery

OBS 28+ bundles WebSocket support. Managed setup uses a local authenticated listener. Milestone 2 connection/password recovery is intended for stopped, confirmed output; it must not start a broadcast or alter ordinary OBS. Follow current setup prompts and source-specific diagnostics rather than exposing the listener publicly.
