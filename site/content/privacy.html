Application data and network actions

Managed stream keys and the generated OBS control password are stored in a private local secrets file, separately from shareable settings. The local setup link is private too. Ordinary OBS configuration remains separate from the managed profile.

Broadcasting connects OBS to your chosen provider. Checking/downloading updates contacts the configured GitHub release channel. Opening an optional funding link contacts that external service. These are different actions; none should silently start a broadcast.

This static preview loads no analytics, external fonts, remote scripts or tracking images. Serve its local files over loopback without an external network; external links need connectivity. A future hosting provider's request logging is not decided or represented by this local preview.

Diagnostics and reporting

The console exposes bounded, filtered events. Stream keys, passwords, credential-bearing URLs and raw OBS output should not appear. Review material before sharing it; include versions and visible failure stages instead of private configuration.

The managed WebSocket is local and authenticated. Do not expose it publicly to work around startup failure. Use supported stopped-state recovery controls and preserve output-state safety checks.

Optional support and crypto

Funding links are derived from the owner's repository funding configuration. Configured handles do not establish payout readiness or payment-service availability. Support is voluntary and does not unlock local Start/Stop, recovery, accessibility or diagnostics.

Cryptocurrency destinations appear only after public receiving addresses are configured. A destination identifies a specific network; verify it and the full receiving address before sending. The project does not need a private key or recovery phrase, and this preview does not create a wallet, sign a transaction or move funds.
